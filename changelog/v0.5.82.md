# Changelog v0.5.82 - 2026-09-05

### Added
- 🧬 **Family-preserving failover (Smart Router)**: when a routed model fails (429, 5xx, timeout...), the router now first retries the **same model family on another provider** (e.g. DeepSeek down on NVIDIA NIM → DeepSeek on SambaNova) before falling back to the next entry in your set. Your coding assistant keeps the same model behaviour mid-conversation instead of silently switching to a totally different family. 12 families detected: Claude, DeepSeek, Gemini, GPT, Nemotron, Llama, MiniMax, Qwen, Kimi, GLM, Mistral, OpenAI o-series.
- 🔘 **Per-set "Family failover" toggle**: new button on the Web Router Dashboard's set panel (on by default, stored as `familyFailover` in the set config, also settable via `PUT /sets/:name`). Turning it off restores the historical strict set-order failover.
- 🏷️ **Family hops are visible**: request-log entries now carry a `failover_reason` (`family_failover` or `set_order`), surfaced in the TUI Router Dashboard, the Web Dashboard request log (`family` tag), the `/stream/events` SSE `request` event, and the `app_router_failover` telemetry event.

### Changed
- 📖 Docs: README "Failover order" section and TUI help now explain family-preserving failover and the toggle.
