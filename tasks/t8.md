# Family-based cross-provider failover

> **Priority**: P3 — extends the existing router failover (which already retries *within* a set) to switch **across providers** when the same model family is available elsewhere. Builds on the daemon; doesn't affect CLI ping.
> **Inspiration**: `apmantza/pi-free` — `lib/model-detection.ts` (family mapping) + their `provider-failover/` directory.
> **Cross-surface**: daemon-side; transparent to all client surfaces.

---

## 1. Why

The FCM Router (per `tasks/PRD-smart-model-router.md`) already does failover **within a set**: if `nvidiaNim/deepseek-v4-pro` 429s, it tries the next model *in the set list*. But the next entry might be a totally different family (Qwen, Llama) — the user asked for DeepSeek-class output and gets a behaviour change mid-conversation.

pi-free's `lib/model-detection.ts` normalizes every model to a **family** (`claude`, `deepseek`, `gemini`, `gpt`, `llama`, `minimax`, `qwen`, `nemotron`, `kimi`, `glm`, `mistral`, `arcee`, `openai-o`). Combined with their failover dir, they can reroute `OpenRouter/deepseek-v4` → `Cerebras/deepseek-v4` → `Together/deepseek-v3` keeping the user in the DeepSeek family.

This task makes the router prefer **family-preserving** failover: when a model fails, look for the same family on another provider before falling back to a different family.

---

## 2. Goals / Non-goals

### Goals
- [ ] Normalize every model in our merged list to a `family` id (12 families, mirror pi-free's `BRAND_MAPPINGS`).
- [ ] When a routed request fails, prefer retrying on a healthy model of the **same family** at a different provider.
- [ ] Fall back to the existing set-order failover when no same-family alternative exists.
- [ ] Surface the failover decision in `/stream/events` (already emits `request` events) and the Router Dashboard TUI.
- [ ] Configurable: per-set toggle `familyFailover: true|false`.

### Non-goals
- Family detection for ping (we only need it at routing time).
- Cross-family "equivalence" scoring (e.g. treating Qwen as DeepSeek-equivalent) — explicit family match only.
- Replacing the circuit breaker (it still gates each (provider,model) pair).

## 3. Technical design

### 3.1 Family detection: `src/core/model-family.js`

Port pi-free's `BRAND_MAPPINGS`:

```js
const BRAND_MAPPINGS = [
  { keywords: ['claude'],          familyId: 'claude',   familyName: 'Claude' },
  { keywords: ['deepseek'],        familyId: 'deepseek', familyName: 'DeepSeek' },
  { keywords: ['gemini'],          familyId: 'gemini',   familyName: 'Gemini' },
  { keywords: ['gpt'],             familyId: 'gpt',      familyName: 'GPT' },
  { keywords: ['llama'],           familyId: 'llama',    familyName: 'Llama' },
  { keywords: ['minimax'],         familyId: 'minimax',  familyName: 'MiniMax' },
  { keywords: ['qwen'],            familyId: 'qwen',     familyName: 'Qwen' },
  { keywords: ['nemotron'],        familyId: 'nemotron', familyName: 'Nemotron' },
  { keywords: ['kimi','moonshot'], familyId: 'kimi',     familyName: 'Kimi' },
  { keywords: ['glm','chatglm'],   familyId: 'glm',      familyName: 'GLM' },
  { keywords: ['mistral'],         familyId: 'mistral',  familyName: 'Mistral' },
  { keywords: ['o1','o3'],         familyId: 'openai-o', familyName: 'OpenAI o' },
];

export function detectFamily(model) {
  const haystack = [model.id, model.label, model.providerKey]
    .filter(Boolean).join(' ').toLowerCase();
  for (const m of BRAND_MAPPINGS) {
    if (m.keywords.some(k => haystack.includes(k))) return m.familyId;
  }
  return null;
}
```

### 3.3 Failover policy change (in `router-daemon.js`)

Today (per PRD): failover iterates the set list top-down. Change to two-stage:

```js
function pickNextModel(failedModel, set, circuitBreaker) {
  // Stage 1: same family, healthy, different provider
  const family = detectFamily(failedModel);
  if (family && set.familyFailover !== false) {
    const sameFamily = set.familyIndex.get(family) ?? [];
    const candidate = sameFamily.find(c =>
      c.providerKey !== failedModel.providerKey &&
      circuitBreaker.isOpen(c.providerKey, c.modelId) === false
    );
    if (candidate) return { ...candidate, reason: 'family_failover' };
  }
  // Stage 2: existing set-order fallback
  return set.nextInOrder(failedModel) ?? null;
}
```

### 3.4 Observability

- `/stream/events` `request` event gains a `failoverReason: 'family_failover' | 'set_order' | 'none'`.
- Router Dashboard TUI request log shows the family hop (e.g. `nvidiaNim/deepseek-v4-pro → together/deepseek-v3  [family]`).
- Telemetry: `router_family_failover` event (sampled).

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Family detection false positives (`o1` matching inside `gpt-oss-120b`'s id? — check: `gpt` matches first, so fine; but `o1` keyword must be word-boundary-checked) | Order `BRAND_MAPPINGS` so `gpt` precedes `openai-o`; add tests for the tricky ids in `sources.js`. |
| Family hop hides a provider outage from the user | Surface it loudly in the dashboard + telemetry; don't silently swallow. |
| User wants strict set order | `familyFailover:false` per set; default `true` but documented. |
| Different providers expose different context windows for the "same" family | Acceptable — failover is best-effort; the alternative (conversation-breaking family switch) is worse. |
